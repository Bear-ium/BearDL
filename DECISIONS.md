# Decisions

- **eframe glow, not wgpu.** eframe 0.37 defaults to wgpu. glow is several MB smaller and gives mpv's OpenGL render API a GL context.
- **No `default_fonts`.** Bundled egui fonts add ~1 MB. The app loads the platform UI font at startup (Segoe UI and Segoe UI Symbol on Windows, SF/Helvetica on macOS, DejaVu/Noto/Liberation on Linux). The optional `bundled-fonts` feature restores egui's fonts for systems without any of them.
- **No accesskit.** It saves size, but costs screen-reader support. This can be revisited.
- **Release `opt-level = "s"`.** Baseline window: z = 3.96 MB, s = 3.36 MB, 3 = 3.90 MB. "s" is smallest here. This is re-measured in M9.
- **System curl and tar instead of an HTTP/TLS crate.** Windows 10 1803+, macOS and nearly all Linux distros ship both. On Windows they are called from `%SystemRoot%\System32` so Git's copies don't shadow them. This saves ~2 MB of TLS stack. Downloads are verified with SHA-256 (`sha2`).
- **libmpv via hand-written FFI and `libloading`.** `libmpv2`/`libmpv-sys` link at build time, so the exe would not start without the DLL.
- **Tray.** Windows uses a hand-rolled `Shell_NotifyIconW` (windows-sys is already in the tree via winit), which also provides balloon notifications. macOS and Linux use `tray-icon`, with the `ksni` backend on Linux so GTK is not needed. Notifications on Linux and macOS go through `notify-send` and `osascript`, not notify-rust and its zbus stack.
- **Global rate limit.** yt-dlp only limits per process, so each process gets `global / concurrency`. All of them together never exceed the limit, though fewer running downloads use less of it. An earlier per-start split could exceed the limit, so it was replaced.
- **Title filters are comma-separated keywords** (case-insensitive substring match), not regex. This avoids the regex crate.
- **Cold start is measured from launch to the second painted frame**, using wall-clock timestamps written by `BEARDL_STARTUP_LOG`. Process teardown is excluded: the GL driver takes ~700 ms to unload. About 200 ms of the 233 ms baseline is window and GL context creation, which egui cannot avoid.
- **Idle memory is ~70 MiB private at baseline.** Nearly all of it is the OpenGL driver (NVIDIA). The app's own heap is a few MiB.
- **M0 review folded into M1's.** The M0 diff is a 100-line scaffold, so its review runs together with M1's.
- **yt-dlp uses the PyInstaller "onedir" zip builds** (`yt-dlp_win.zip`, `yt-dlp_macos.zip`, `yt-dlp_linux.zip`). Every yt-dlp run is a new process, and the single-file builds unpack about 25 MB to a temp folder on each launch. If an archive can't be extracted (Linux with no bsdtar, unzip or python3), the single-file asset is installed instead.
- **Updates resolve the release tag once** and fetch checksums and asset from `releases/download/<tag>/`. Nightly and master publish often, so separate `latest` lookups could mix releases.
- **Rollback pins the build.** The checksum of the build rolled back from is stored as `rejected_sha`, and auto-update skips it until a newer release appears.
- **ffmpeg comes from PATH when present.** It is downloaded only when missing, on first run or with the button, and is never auto-updated (about 140 MB). A newer build is shown when the managed copy is out of date.
- **M1 review follow-ups.** The fixes in this commit cover: shutdown hang, curl stall timeouts, rollback pinning, single-tag resolution, safe rotate, path fields applying on blur, channel-change check, first-run ffmpeg, onefile fallback, atomic state file, and the messages. Deferred:
  - Unused deps are scheduled: `serde_json` and tokio `io-util` arrive in M2, the windows-sys features in M7.
  - The extra HEAD request per tool download is kept for progress totals, since it happens only on tool updates.
  - Skipping auto-install while downloads run lands in M2 with the queue.
- **M1 cold start.** In-process time to the second frame is unchanged from M0 (~240 ms). The external figure varies by ±50 ms with process loading and Defender scanning of the larger exe.
- **yt-dlp runs with `--ignore-errors`.** A subtitle 429 or a failed thumbnail must not lose the video. A run counts as successful when yt-dlp prints the final path (`after_move`). Exit 0 without a file means Skipped (filtered out or already archived).
- **The default subtitle languages are `en,en-US,en-GB`, not `en.*`.** On YouTube, `en.*` also matches dozens of auto-translated tracks and triggers HTTP 429.
- **Custom arguments are validated by yt-dlp itself.** The run uses `--simulate` and a URL that cannot be fetched; a usage error (exit 2, `error:` on stderr) means invalid. `--version` as a terminator was tried and does not work: yt-dlp accepted unknown options before it.
- **The reserved-option check** covers what yt-dlp's optparse would accept: unique prefixes of long options, short-flag clusters, a bare `--`, and stray URLs. `--exec` stays allowed, because presets are the user's own. Imported presets are shown before use (M4).
- **Process trees.** On Windows each yt-dlp runs inside a Job Object with kill-on-close, so pause, cancel, app exit and even a crash also kill the ffmpeg it started. On Unix each runs in its own process group, which gets SIGKILL. This replaced the blocking `taskkill /T`.
- **Queue reorder** writes one row, at the midpoint between its new neighbours. It renumbers only when positions converge.
- **Quick Download of a playlist or channel** expands it into one item per video. A channel root opens its Videos tab.
- **Without ffmpeg**, downloads fall back to the best single-file format, and conversion, merging and embedding are skipped, with a one-time notice. The queue waits while an ffmpeg install is in progress.
- **Thumbnails are not embedded into WAV or WebM**, which do not support it.
- **M2 review items not changed:**
  - The analysis spinner animates while yt-dlp runs. It only lasts a few seconds.
  - Downloads without a known total show bytes instead of an animated bar, so a live stream doesn't repaint continuously.
- **M2 is measured before its review fixes.** M3 re-measures.
- **Import safety (from two security reviews).** An export file is untrusted input, so import:
  - never changes the yt-dlp, ffmpeg or mpv paths, in either mode;
  - lets imported presets and subscription configs keep custom arguments only if every option is on a fixed allowlist of known-safe yt-dlp options, spelled in full; anything else clears that preset's custom arguments, with a warning. A denylist was tried first and replaced, because `--alias` and option prefixes can get around one;
  - in merge mode, never overwrites a different local preset of the same name; the imported one is renamed "(imported)";
  - writes theme files only inside the themes folder, under sanitised names.

  Presets the user writes by hand are still free to use any option, apart from the ones the app reserves.
- **Library sort indexes are partial (`WHERE status != 'queued'`)**, matching the library filter. This took deep pages from about 65 ms to a few ms at 100,000 rows. Schema changes are versioned with `PRAGMA user_version`.
- **SQLite page cache is 16 MiB.** With the default 2 MiB, bulk inserts thrashed: 100k rows took 23 s, now 4.6 s. The cache only grows when it is used.
- **100,000-entry library, release build:**
  - count: 3 ms
  - search count: 12 ms
  - first page: 0.1 ms
  - page at row 99,900 sorted by title: 4 ms
  
  The list is virtualised, so only visible pages of 100 rows are loaded.
- **Library search is debounced by 250 ms**, so a fast typist does not run a query per keystroke.
- **Moved-file detection** looks for a file with the same name **and size** under the download folder (4 levels, 200k files max, no symlinks or junctions). It only re-links when no other entry already uses that file. Anything else is flagged as missing.
- **Delete with file** removes a file only if the entry is Done and no remaining entry points at it, since re-downloads can share a path. It removes thumbnails only from the app's cache folder.
- **Thumbnails.** Small list copies (192 px) are made by ffmpeg after download and written atomically. Decoding happens on one worker thread, newest request first, using JPEG DCT scaling. The texture cache allows 400 small and 6 large (quick view) textures. With `panic = "abort"` a decoder panic cannot be caught, but jpeg-decoder reports malformed input as errors.
- **Quick view and list rows** resolve file existence, chapters and thumbnail paths once per refresh, not per frame.
- **Themes are TOML files** with optional `[colours]`, `[fonts]` and `[spacing]`, falling back to egui's light or dark base. A theme is applied only when the selection, a reload or an import changes it; `set_fonts` runs only when the font path changes. A theme font is used only if it is a local file under 50 MiB that parses as a font, because epaint panics on bad fonts. UNC paths are refused. Non-finite numbers and non-ASCII colours are rejected, not panicked on.
- **The example theme** (`midnight.toml`) is written once, tracked by a marker file. Deleting it does not bring it back.
- **Import never chooses where files go or what runs (M4 review).**
  - Settings keep the local download folder, file-name template and tool paths.
  - Preset and subscription folders and templates must be relative, with no `..`.
  - Imported themes lose `fonts.family`.
  - Merge never overwrites local presets or theme files; it adds "(imported)" or "-imported" copies.
  - Files over 16 MiB are refused.
  - Theme write errors become warnings, not a failed import.
  - Export writes atomically. It does not ask before overwriting, since the user types the path.
- **Embedded player.** libmpv is loaded at runtime (`libmpv-2.dll`, `libmpv.so.2` or `libmpv.2.dylib`; the app folder, `tools/mpv`, Homebrew paths and the system search path are tried, and `BEARDL_LIBMPV` overrides). mpv renders through its OpenGL render API into an FBO texture registered with egui. FLIP_Y is 0, because egui samples texture row 0 as the top. mpv's update callback requests a repaint only when a new frame exists, so a paused player is idle.
- **The player is driven from `App::logic`.** eframe calls `logic` (not `ui`) while the window is minimised or covered, and mpv waits for each frame to be rendered, so video keeps playing when the window is hidden. `GL_BLEND` is switched off before mpv renders, because egui leaves it on.
- **Resume positions** are saved every 15 s while playing, on pause or switch, and on exit. They are read fresh from the database at play time. Within 10 s of the end counts as finished.
- **Without libmpv**, playback goes to an external mpv (`--start=… -- file`), else the system player, with install instructions. Metadata, thumbnails and chapters are embedded by yt-dlp at download time (`--embed-metadata --embed-thumbnail --embed-chapters`); ffprobe confirmed the tags and the attached cover.
- **For testing only**, a libmpv build was downloaded into the session's scratch folder and pointed to with `BEARDL_LIBMPV`. It is not bundled.
- **M5 and the start of M6 share one commit.** They touch the same UI files. M6's review fixes get their own commit.
- **Subtitle indexing.** Subtitles are written to the app cache as `<extractor>-<id>.<lang>.vtt` and converted to VTT when ffmpeg is present. They are found by that name, because yt-dlp's reported `filepath` can be stale. The default languages are `en,en-US,en-GB,.*-orig`, which adds the original-language captions so non-English videos are indexed in what was said. One track per base language is indexed: manual first, then `-orig` captions. Auto captions are recognised by YouTube's `kind=asr` URL.
- **The parser is line-based**, to handle blank lines that hold spaces, missing separators, lone CRs, numeric entities and `{\an8}` tags. Folding repeated lines is applied only to automatic captions, so real repeats in manual subtitles stay.
- **Cue index (schema v3).** The FTS5 `cues` table has `prefix='2 3'`. Each track stores the rowid range of its cues, so deleting cues is a range delete; `download_id` is UNINDEXED in FTS5, so deleting by it would scan everything. Re-indexing a video replaces the cues of earlier downloads of the same video. Shared subtitle files are never deleted while referenced.
- **Search queries run on a worker thread** with their own connection. The engine bumps `library_rev` after indexing finishes, so open search results refresh.
- **Subscriptions.**
  - Each check runs `yt-dlp --flat-playlist -j`. Channels list newest first, so `--playlist-end <items>` applies. Playlists list oldest first, so they are listed in full and reversed before planning.
  - Every listed ID goes into `sub_seen`, including filtered ones, so only genuinely new items are queued.
  - On the first check, the newest *N* are queued, or none with "Only future uploads". A failed first check keeps its first-check status.
  - YouTube channel root URLs get `/videos` appended. A listing of only tabs is logged as an error.
  - Checks time out after 5 minutes.
  - The engine has a single timer: it sleeps until the sooner of the next subscription check and the next update check, capped at 15 minutes because the monotonic clock may not count suspend. Due times are clamped to one interval if the clock goes backwards.
  - Checks wait while yt-dlp is missing or updating. Updates wait for running checks.
- **Tray.**
  - Windows has a hand-rolled `Shell_NotifyIconW` tray on a hidden top-level window (not message-only, so it receives TaskbarCreated after an Explorer restart). Its menu has Show, Check subscriptions and Quit. Notifications are balloons, and the icon is removed synchronously on exit.
  - macOS and Linux use `tray-icon`, with the ksni backend on Linux (no GTK). Notifications go through `osascript` or `notify-send`, with markup escaped and the child process reaped.
  - Close-to-tray (`CancelClose` plus `Visible(false)`) was verified: after a close request the process keeps running with its window hidden. It is off by default on Linux, where many desktops show no tray.
- **Start with the OS** uses the HKCU Run key on Windows, a LaunchAgent plist on macOS, and `~/.config/autostart/*.desktop` on Linux (AppImage aware, with Exec escaping). It starts with `--minimised`. eframe always shows the window after its first frame, so the window is hidden on the second; a minimised start was verified to leave the main window hidden. The entry is refreshed at start, so it follows the program if it moves.
- **The status bar has no spinner.** A background update check animated it at 60 fps for its duration. The bar now shows static text.
- **Trimming.**
  - Fast mode copies streams (`-ss`/`-to` before `-i`, `-map 0 -map -0:d -c copy`) and starts at the keyframe before the start.
  - Accurate mode re-encodes video and audio only.
  - A clip's duration is probed with ffprobe.
  - Trims run one at a time. Partial outputs are deleted on failure or exit.
  - Clips go next to the source, or to the download folder if that is read-only. They become new library entries (dated now, no subscription) that share the source's thumbnail.
  - The preview is an mpv A-B loop, cleared when a new file opens.
- **M7 and M8 share one commit**, because their review fixes touch the same engine and player files.
- **M9 profile comparison (full app).** `s`: 5.56 MiB. `z`: 5.87 MiB. `3`: 7.24 MiB. Cold start (243–257 ms) and idle memory are the same within noise, so `opt-level = "s"` stays. Unused windows-sys features (`Win32_Graphics_Gdi`, `Win32_Security`, `Win32_System_Threading`) were removed.
- **Idle profile.** A frame trace shows two frames at start, then none while idle, and no engine wake-ups. 70–75 MiB private memory is almost all the OpenGL driver.
- **The tools' "cancel downloads" flag is cleared when an engine starts.** It stayed set after one engine shut down, which broke a second engine in the same process; only the test suite does that.
